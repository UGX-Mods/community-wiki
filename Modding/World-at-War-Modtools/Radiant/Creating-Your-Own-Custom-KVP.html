Entities in Radiant get their settings through key-value pairs (KVPs), like targetname or script_noteworthy . Only keys that the game knows are available in script. If none of the existing keys fits your needs, you can declare your own.

Look through the existing keys first: often there is already a key you can use (for example script_noteworthy or script_string ).

Declare the key

All keys that are accessible in script are listed in raw\radiant\keys.txt . Each line starts with the type of the value, followed by the key name. Add your keys at the end of the file, for example: 

string zc_door_part
string zc_cold_type

Keys that client scripts (CSC) need are declared the same way in raw\radiant\clientkeys.txt .

Add the keys files to your zone file

The game reads the keys from the fastfile of your map, so add the files as rawfiles to the zone file of your map ( zone_source\<mapname>.csv ): 

rawfile,radiant/keys.txt
rawfile,radiant/clientkeys.txt

Then compile your map and build the fastfile again.

Use the key in Radiant and script

Select the entity in Radiant and add the KVP like any other, for example zc_door_part | handle . In script, the value is available as a field of the entity: 

parts = getEntArray( "door_parts", "targetname" );
for ( i = 0; i < parts.size; i++ )
{
	if ( isDefined( parts[i].zc_door_part ) && parts[i].zc_door_part == "handle" )
	{
		// ...
	}
}

If the field is undefined in game although the KVP is set in Radiant, check that the key is spelled the same in keys.txt and on the entity, and that the zone file contains the rawfile lines.
